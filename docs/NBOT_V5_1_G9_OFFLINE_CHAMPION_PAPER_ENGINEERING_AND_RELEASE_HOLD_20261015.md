## 1. Conflict and design decision — the first Champion does NOT wait for a Challenger

Vision V1.9 §§8C–8E explicitly authorize *future* first Champion-only PAPER after G8 scientific qualification and independent owner paper authorization, followed *later* by qualified Challenger comparison (G10). Historical R22 `nbot/v5/guarded_paper.py`, immutable legacy commit `91d904b0e3783a93266f4ff646414bbb8fcc3333`, Git blob `5d826d5a5583382a96da0cc49663006ed540720d`, required BOTH `CHAMPION_PAPER` and `CHALLENGER_PAPER` and both qualified models/keys before unlock. That contradicted the approved lifecycle. Historical R23 `nbot/v5/execution_engine.py`, commit `4f7331c12233260b9422f1ff4ff9711d9b992a30`, Git blob `5942ca0f7300b3bc41864aa9877cb7f38a258708`, represents an incompatible second SQLite/offline-execution design.

**Resolution:** V5.1 uses ONE new Champion-first paper-book *contract* with at most ONE simulated position. It can exercise an offline *synthetic LAB* book without requiring any Challenger. The real owner-approved initial Champion PAPER capability is **unimplemented/locked**, and the old two-model gate is NOT simply bypassed. Future G10 challenger uses separate isolated paper account and a separate release, never shares this synthetic research ledger or authority. No old SQLite paper runtime or duplicate execution subsystem copied.
