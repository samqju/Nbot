## What the user actually means by “best possible outcome”

A backtest can always identify the *historical trade that turned out best* if it looks into future prices. That is **hindsight** and would give false backtest results. We must rank by the **best predicted, conservative, after-cost outcome using ONLY what was known at decision time**. We can then separately score the actual realized Freqtrade native result later.

At each completed 5-minute candle, if the previous trade is closed:

1. Generate only **valid current** entries (no forced signal) for all 25 point-in-time tradeable contracts, across original breakout/pullback and eight additional families, both sides when each setup's valid long/short entry signal fires. Up to 25×10×2=500 theoretical (coin, setup, direction) slots; most should produce no candidate on a given candle. Filter by point-in-time liquidity, exchange availability, regimes, protections, 1x and 1000 USDT one global position.
2. Query genuinely **already fitted** LightGBM models for each family/coin (or a rigorously trained shared conditional model) with strict training-label embargo, no future features and a model fitted before the candle. Each reported number must have the same **predicted net return fraction**, identical forecast horizon or exit policy, calibration standard, funding/fees/slippage accounting, and comparable expected downside. Different target definitions, gross-vs-net predictions, or exit policy durations may not be ranked together.
3. Refuse stale/outlier/uncalibrated predictions, unvalidated families, excess uncertainty or risk, weak liquidity and large assumed extra trading cost. The conservative score should subtract estimated model uncertainty, incremental execution cost and an explicit penalty for plausible downside, **not choose the largest raw return prediction automatically**.
4. Select **only one** globally highest *credible positive* candidate over the same 25-coin snapshot. Or choose **NO TRADE** when no opportunity is sufficiently attractive, when one global position is already occupied, or when required data is missing. Keep an auditable ledger of *all accepted AND rejected* candidates with timestamp, model, family, side, fees, reason and whether it would subsequently have won/lost.
5. Feed that deterministic as-of winner into a **single real Freqtrade native 25-market historical portfolio replay** with actual simulated entry/exit, 0.05% fee each side, modeled funding, identical exits, 1×, one 1000 USDT global position, native safeguards and additional hypothetical 10/15/25bp cost stresses. Compare with **NO TRADE=0**, the matched original breakout/pullback aftercost AI baseline, each nonAI standalone family, the best fixed family policy chosen on prior data, the 8h regime-only selector, and a ranker without AI calibration. Annual native strategy-retraining and testing windows must not use later performance to select an earlier winner.
6. Change or introduce trailing/profit-protection policies **only after** the current 8-family batch and already-queued 120 additional exit-policy native tests finish; candidates under different exit policies are **not** comparable until their forecasts and cost/risk targets are normalized and tested under the chosen frozen exit policy.

A research score can be higher on one coin/strategy while the actual simulated trade ultimately loses. The objective is *calibrated statistical selection*, not certitude or automatic profit. Repeated model/strategy searches heighten overfitting risk; require historical chronological train, independently validated periods, and a genuinely new never-inspected future holdout.
